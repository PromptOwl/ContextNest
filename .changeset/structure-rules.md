**Structure rules: a nest owner can enforce folder layout, naming formats, placement and templates.**

- New optional `.context/config.yaml` keys (spec §11.1.1): `structure` (`enforce`, `closed`), path-pattern `folders` entries with `types`, `folder_name`, `file_name` (token patterns like `{date}-{slug}` or a guarded `/regex/`), `template`, `required` and `files`, and named `templates` with `required_sections`.
- Every write enforces them when `structure.enforce` is true — `context_create`, `context_update`, `context_delete`, `context_import` (both `files[]` and `documents[]`, with a refused document's history and folder files refused too), `context_import_pdf`, approving a held edit (`approveReview`) or drift suggestion (`approveSuggestion`), every publish (`publishDocument`/`publishDocuments` judge it: a first publish in full, a later one against the last sealed version — so `context_publish`, `context_import ids[]`, `context_update publish:true`, review approval and the legacy tools all agree; an import overwrite is judged as its publish before it lands; history that cannot be rebuilt is judged in full and never blocks the publish that repairs it, and a refused publish quarantines nothing; grandfathering trusts only a sealed head that rebuilds, versions strictly increasing, and matches its own content hashes (`sealedHead`), judged in the normalized view those hashes cover, with headings read by one line model (CR, LF and CRLF each end a line, as CommonMark does) for the live file and the head alike; a segment over 1000 entries, or whose replay walks over 128 Mi characters (the text's length once per diff, counted as it replays), is not trusted; a forget stub (`status: forgotten`, empty body) owes no required sections, so an enforced vault's own export round-trips, and grants nothing as a baseline; an imported history's head is judged as an update over the head the vault holds now (so a grandfathered document's own export restores over it); an unreadable on-disk history refuses its set, an unparseable one may be replaced; an import judges only files that will land (a refused file takes its history with it, `history.yaml` is written last) and judges a document against the head its history will have after the call, and an import is refused when the history the vault will hold after it (its files over what is there — under its own `history.yaml` and under the one already on disk) does not rebuild and verify, or ends in a version the full check refuses — a document may still arrive before or after its history; an import refuses any path spelling a machinery folder another way (`.versions::$DATA`, `.ver\u200Bsions`), so a decoy never vouches for the files beside it; an import never replaces a sealed PDF binary — sidecar (judged against the bytes on disk, or the sealed head's `pdf.sha256` when none are there) or archive — with other bytes, judged on bytes first, so the same bytes always land and neither a retyped `.md` nor an unverifiable history frees a pdf node's sidecar; a `.pdf` beside an ordinary document is an ordinary file whose replaced bytes are archived first, and a never-sealed node takes the sidecar its `.md` names; a refused document or sidecar takes its family (the other of the pair, its history), a refused archived PDF does not; a document's `.versions/` folder takes no nested paths; the history already on disk is judged with the call's files only where their bytes match its pinned hashes, and only when that changes its head; new PDF versions come through `context_import_pdf`), `ctx pull`, and the deprecated MCP `create_document` / `update_document` / `delete_document`. Refusals are `VALIDATION_FAILED` with a message naming the rule and the expected format; a rule that does not compile refuses writes with `CONFIG_ERROR` only in an enforced vault, never blocks reads, and `context_structure` reports it as `error`. Report-only rules write and refuse nothing. Existing content is grandfathered. Existing `folders:` blocks (template labels, any folder name) keep working.
- Owner regexes are restricted to an exact grammar (no repeated groups, ≤ 3-digit quantifier bounds, literal braces/brackets escaped) and matched by a linear-time position-set matcher — never the backtracking engine; token patterns run on it too, and classes follow ECMAScript Annex B (`[\d-z]` is a union, not a range). Malformed rule keys no longer make the config unreadable; they refuse writes only in an enforced vault. The reserved-path guard runs on every publish and folds case fully (`ſ`), drops NTFS `:stream` suffixes and refuses control characters. `NestStorage.init` keeps the rules over a re-init (and refuses a config that is not YAML but names them), and `ctx init` filters starters through them and publishes them as one batch. `enforce` other than `true`/`false`, or a `structure` that is not a mapping, is a CONFIG_ERROR, never off (`isEnforced`; `context_structure` reports it as enforced). First publishes scaffold in one directory crawl per top-level folder and one linear subtree pass (deep ids and wide batches no longer hold the vault lock), and only published or approved documents occupy a folder. `structure: false` is off. Re-init refuses any config that is not valid YAML. Imported file paths are size-checked before writing, reads measure the `.md` file an id names, and import failures report vault-relative paths, so no error reports the vault's absolute path. Imports keep `INDEX.md`/`README.md` names (refused beside another spelling of the name), key a `./`-spelled document's history as its slug does, and plan colliding names in linear lookups. Heading parsing and rule-key trimming are linear. `setStructure` refuses a config symlinked outside the vault. Token patterns are limited to ≤ 3 non-adjacent variable-width tokens, rule sets to 256 folder rules, and each (format, name) is evaluated once per check.
- No create, update, import or publish touches a document under `.context/`, `.versions/`, `_suggestions/` or the root `packs/`, or with a `\` or control character in its id, or an id over 1024 characters or with a name over 251 bytes (`assertWritableDocumentId`; an update checks before it writes; trusted restores are not exempt; rollbacks, czar direct edits and suggestion approvals too, via `commitNewVersion`). Deletes and forgets — imported forgets included — refuse `.context/`, `.versions/` and `_suggestions/` paths (`assertErasableDocumentId`; `assertNotMachineryPath` also backs `NestStorage.writeDocument`/`deleteDocument`), and an imported forget record naming no document of the vault (`../`) is neither logged nor applied. A name with `~` and a digit is checked where it resolves (`assertResolvesOutsideMachinery`, on every write and erase): an NTFS short name (`VERSIO~1`) for a reserved folder is refused, while `Plan~2` stays an ordinary, writable and erasable name. Name comparisons drop default-ignorable code points (HFS+ ignores them). Rules compare roots and exemptions exactly; enforced rules refuse another spelling of the content root (`NODES/`, `nodes./`, `nodes:x/`) as `FOLDER_NOT_ALLOWED`, since one volume reads it as `nodes/` and another as an unjudged folder. Vaults without enforced rules are unaffected; under enforced rules, existing `Nodes/` documents stay editable (grandfathered) but cannot be newly created there. A rule key's `Nodes/` prefix matches without case.
- An enforced write that creates a folder also creates its required subfolders and files (drafts from their templates; best effort, never failing the write). A write held for review is scaffolded on its first publish, whichever surface approves it (`scaffoldFirstPublish`). A required file can be deleted only as the last document in its folder.
- New core op `context_structure` (`folder`, `report`) — on the MCP server automatically, and as `ctx structure [--folder] [--report] [--json]`, local and remote with identical JSON. `ctx add` without `--body` starts from the folder's template.
- New engine exports: `enforcedStructure`, `missingFolders`, `scaffoldFolders`, `scaffoldFirstPublish`, `assertStructurePublish`, `structurePublishViolations`, `isEnforced`, `assertStructureUpdate`, `assertStructureDelete`, `assertWritableDocumentId`, `assertNotMachineryPath`, `assertErasableDocumentId`, `assertResolvesOutsideMachinery`, `assertWritableDocumentPath`, `machineryAliasSegment`, `sealedHead`, `assertFitsFileSystem`, `comparableSegment`, `compileStructure`, `checkDocument`, `checkUpdate`, `checkFolder`, `checkDeleteDocument`, `checkDeleteFolder`, `scaffoldPlan`, `auditStructure`, `resolveFolder`, `describeStructure`, `enforceStructure`, `setStructure` (rewrites only the rule blocks of `config.yaml`), and `OperationContext.structure: "skip"` for trusted hosts restoring a whole vault.
- Behaviour change: a vault can no longer get NEW documents under a root-level `packs/` folder (packs live there); existing ones stay readable but can no longer be published.
- **Security:** an imported `.pdf` in an encrypted vault now lands sealed (it was written as plaintext), and a forgotten PDF's bytes are refused at any path and under any name, not only as an archive, and a `.md` with broken frontmatter is still checked for a forgotten path or body. `context_verify` reports an unreadable version artifact instead of failing the vault. A version artifact that is present but unreadable (a directory, EACCES) is corrupt history, never "missing" (`readKeyframe`/`readDiff`). Heading, section and link scanning and the frontmatter delimiter share one line model (CR, LF, CRLF); `extractSection` returns LF-joined text. `context_import` `files[]` no longer writes anything under `.context/` or a document under the root `packs/` (an import could previously overwrite `config.yaml`, turning off the review gate), and no write op accepts a document id under `.context/` (Windows trailing-dot names included). Trusted hosts restoring a vault pass `structure: "skip"`.
- Plugin: session start shows the pinned/working-directory vault's rules; the capture and curator agents check `ctx structure` before writing.
