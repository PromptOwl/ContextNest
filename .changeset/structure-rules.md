**Structure rules: a nest owner can enforce folder layout, naming formats, placement and templates.**

- New optional `.context/config.yaml` keys (spec §11.1.1): `structure` (`enforce`, `closed`), path-pattern `folders` entries with `types`, `folder_name`, `file_name` (token patterns like `{date}-{slug}` or a guarded `/regex/`), `template`, `required` and `files`, and named `templates` with `required_sections`.
- Every write enforces them when `structure.enforce` is true — `context_create`, `context_update`, `context_delete`, `context_import` (both `files[]` and `documents[]`, with a refused document's history and folder files refused too), `context_import_pdf`, approving a held edit (`approveReview`) or drift suggestion (`approveSuggestion`), every publish (`publishDocument`/`publishDocuments` judge it: a first publish in full, a later one against the last sealed version — so `context_publish`, `context_import ids[]`, `context_update publish:true`, review approval and the legacy tools all agree), `ctx pull`, and the deprecated MCP `create_document` / `update_document` / `delete_document`. Refusals are `VALIDATION_FAILED` with a message naming the rule and the expected format; a rule that does not compile refuses writes with `CONFIG_ERROR` only in an enforced vault, never blocks reads, and `context_structure` reports it as `error`. Report-only rules write and refuse nothing. Existing content is grandfathered. Existing `folders:` blocks (template labels, any folder name) keep working.
- Owner regexes are restricted to an exact grammar (no repeated groups, ≤ 3-digit quantifier bounds, literal braces/brackets escaped) and matched by a linear-time position-set matcher — never the backtracking engine; token patterns run on it too, and classes follow ECMAScript Annex B (`[\d-z]` is a union, not a range). Malformed rule keys no longer make the config unreadable; they refuse writes only in an enforced vault. The reserved-path guard runs on every publish and folds case fully (`ſ`), drops NTFS `:stream` suffixes and refuses control characters. `NestStorage.init` keeps the rules over a re-init (and refuses a config that is not YAML but names them), and `ctx init` filters starters through them. `enforce` other than `true`/`false` is a CONFIG_ERROR, never off. `setStructure` refuses a config symlinked outside the vault. Token patterns are limited to ≤ 3 non-adjacent variable-width tokens, rule sets to 256 folder rules, and each (format, name) is evaluated once per check.
- No create, update, import or publish touches a document under `.context/`, `.versions/`, `_suggestions/` or the root `packs/`, or with a `\` or control character in its id, or an id over 1024 characters or with a name over 230 bytes (`assertWritableDocumentId`; an update checks before it writes; trusted restores are not exempt). Roots are recognised case-insensitively (`Nodes/x` is `nodes/x`).
- An enforced write that creates a folder also creates its required subfolders and files (drafts from their templates; best effort, never failing the write). A write held for review is scaffolded on its first publish, whichever surface approves it (`scaffoldFirstPublish`). A required file can be deleted only as the last document in its folder.
- New core op `context_structure` (`folder`, `report`) — on the MCP server automatically, and as `ctx structure [--folder] [--report] [--json]`, local and remote with identical JSON. `ctx add` without `--body` starts from the folder's template.
- New engine exports: `enforcedStructure`, `missingFolders`, `scaffoldFolders`, `scaffoldFirstPublish`, `assertStructurePublish`, `assertStructureUpdate`, `assertStructureDelete`, `assertWritableDocumentId`, `comparableSegment`, `compileStructure`, `checkDocument`, `checkUpdate`, `checkFolder`, `checkDeleteDocument`, `checkDeleteFolder`, `scaffoldPlan`, `auditStructure`, `resolveFolder`, `describeStructure`, `enforceStructure`, `setStructure` (rewrites only the rule blocks of `config.yaml`), and `OperationContext.structure: "skip"` for trusted hosts restoring a whole vault.
- Behaviour change: a vault can no longer get NEW documents under a root-level `packs/` folder (packs live there); existing ones stay readable but can no longer be published.
- **Security:** `context_import` `files[]` no longer writes anything under `.context/` or a document under the root `packs/` (an import could previously overwrite `config.yaml`, turning off the review gate), and no write op accepts a document id under `.context/` (Windows trailing-dot names included). Trusted hosts restoring a vault pass `structure: "skip"`.
- Plugin: session start shows the pinned/working-directory vault's rules; the capture and curator agents check `ctx structure` before writing.
