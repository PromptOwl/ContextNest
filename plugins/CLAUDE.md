# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

This directory contains **coding-agent plugins** that make agents vault-aware (auto-retrieve context) and self-maintaining (auto-capture knowledge) by driving the `ctx` CLI (`packages/cli`). See the root `CLAUDE.md` for monorepo-wide guidance.

## Commands

Run from the **repo root**:

```bash
pnpm test                 # unit + structural + IO-shell tests (excludes *.regression.test.ts)
pnpm test plugins/__tests__/core.unit.test.ts   # single test file
pnpm test:regression      # e2e suite — builds the CLI first, then spawns it against throwaway vaults
pnpm plugins:sync         # vendor shared/core + fill agent/skill prompt bodies
pnpm plugins:check        # CI guard — exit 1 if any vendored copy drifts from shared/
```

Local plugin testing: `claude --plugin-dir ./plugins/claude-code --debug`

## The vendoring model (critical)

**`plugins/shared/` is the single source of truth. Never edit `plugins/<agent>/core/` or the `<!-- BEGIN SHARED -->…<!-- END SHARED -->` regions of agent/skill markdown files** — those are generated by `scripts/sync-plugins.mjs`, and `pnpm plugins:check` fails CI on drift.

Vendoring exists because installed Claude plugins cannot read files outside their own directory. The sync script:
1. Copies `plugins/shared/core/*` → `plugins/<agent>/core/*` byte-for-byte.
2. Replaces the `BEGIN/END SHARED` region of each agent/skill markdown file with the matching `plugins/shared/prompts/*.md` body (targets are declared in `TARGETS` in the script).

Workflow for any core or prompt change: edit `plugins/shared/`, run `pnpm plugins:sync`, commit both the source and the regenerated vendored copies.

## Architecture

```
shared/        Source of truth: core/*.js hook handlers + prompts/*.md agent bodies
claude-code/   Built Claude Code plugin (vendored core + hooks.json + manifest + agents/skill)
codex/         Planned — README only
gemini/        Planned — README only
__tests__/     Test suite for the whole plugins workspace
```

### Hook flow (claude-code plugin)

- **SessionStart** (`session-start.js`) — injects a compact vault overview, or a warning if `ctx` is missing.
- **UserPromptSubmit** (`retrieve.js`) — effort-toggled retrieval: `off` (nothing) · `search` (cheap `ctx search`, top hits as one-line refs) · `query` (search seeds → map ids→tags via `ctx list` → 1-hop `ctx query`, inject distilled bodies) · `agent` (inject a directive to invoke the `contextnest-retriever` agent).
- **Stop** (`capture-gate.js`) — returns `{decision: "block", reason}` to make the model run the `contextnest-capture` agent before finishing. Loop-safe: always allows the stop when `stop_hook_active` is true. Only blocks on "substantive" turns (tool use or >600 chars of assistant output in the transcript tail); `CONTEXTNEST_CAPTURE_ALWAYS=1` bypasses the heuristic.

### Design contract for core modules

- Each `core/*.js` exports a **pure `run({input, env, exec})`** returning the hook output object (or `null` for "do nothing"), plus a thin IO shell guarded by `isMain(import.meta.url)`. Unit tests call `run()` with a fake `exec` — no subprocess.
- **Agent-agnostic**: nothing imports a Claude-specific API. Config comes from `CLAUDE_PLUGIN_OPTION_*` env vars with `CONTEXTNEST_*` fallbacks (see `getConfig` in `lib.js`), so Codex/Gemini adapters can reuse the files byte-for-byte.
- **Zero runtime deps**, plain Node ≥ 20 ESM, cross-platform (no `jq`).
- Hooks must **never break a session**: IO shells always exit 0 and swallow errors to stderr (`runAsHook` in `lib.js`).
- `exec` (built by `makeExec`) runs `ctx` and transparently falls back to `npx -y @promptowl/contextnest-cli` on ENOENT.
- Vault targeting (`vaultTargets`): pinned alias → just that vault; otherwise fan out across registered vaults (capped at `MAX_FANOUT_VAULTS`); empty registry → let ctx resolve the default vault. The pinned-vault env var is deliberately `CONTEXTNEST_VAULT_ALIAS`, not `CONTEXTNEST_VAULT`, to avoid colliding with the env var the ctx CLI itself reads.

### Test tiers

| File | Tier | Approach |
| --- | --- | --- |
| `core.unit.test.ts` | Unit | Calls `run()` with fake `exec` — no subprocess |
| `io-shell.test.ts` | IO shell | Spawns `node <script>` with piped stdin on paths that don't need a real ctx |
| `structure.test.ts` | Structural | Validates manifest, hooks.json, frontmatter, and shared/vendored sync |
| `retrieval.regression.test.ts` | e2e | Spawns the built CLI (`packages/cli/dist/index.js`) against throwaway vaults — only via `pnpm test:regression` |

When adding a plugin config option, it must be wired in three places: `plugin.json` `userConfig`, `getConfig()` in `shared/core/lib.js` (both env var forms), and the structural test's expected key list.
